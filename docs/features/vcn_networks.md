# Verv Closed Network

Каждая именованная сеть VCN соответствует одному экземпляру Headscale.
В кластере узлы используют общий реестр сетей в Postgres. VPN-сайдкар
запускается на узле, на котором сервис подключается к сети.

- **Deploy** создаёт управляемый сервис Headscale с именем `vcn-<name>`.
  Конфигурация, база Headscale и ключ управления хранятся на отдельном
  Docker-томе. В кластере Velez также регистрирует сервис и сохраняет в
  Postgres копию URL и ключа управления для доступа с других узлов.
  В одноузловом режиме Velez находит сети по меткам контейнеров и
  читает ключ из контейнера.
- **External** проверяет URL и токен через API Headscale. Реквизиты
  подключения хранятся только в Postgres. Удаление внешней сети
  удаляет её регистрацию в Velez.
- При удалении управляемой сети Velez удаляет контейнер и его том на
  узле размещения. Удаляются база Headscale, ключи и записи об участниках.

В кластере вызывайте RPC развёртывания по имени узла или IP-адресу,
доступному другим узлам. Разрешите доступ к опубликованному TCP-порту
Headscale. Velez берёт имя хоста для URL подключения из запроса. Если
порт не задан, используется свободный порт из пула узла. При запросе
через loopback в одноузловом режиме Velez использует шлюз Docker.

Все VPN-сайдкары именованной сети используют пользователя Headscale
`velez` на её экземпляре. Для окружений отдельные пользователи не
создаются. Управление ACL находится за рамками этой реализации.
Передайте `network_id` в `ConnectService`, чтобы задача получила URL
подключения и многоразовый ключ из выбранной сети. Запросы без
`network_id` используют существующую конфигурацию VPN.
`GetNetwork` возвращает участников сети и метаданные ключей API.
Значение нового ключа возвращается один раз при его выпуске.
